## Why this site exists

Most material about AI-assisted engineering assumes you set up the AI. In many
organizations you didn't: a platform team owns the Claude deployment, the
managed settings on every laptop, the GitHub org policy, and the list of MCP
servers you may connect to — and security owns the policy about what source
code and which documents may leave the building. You own your team's repos,
CI, tests, and onboarding. This guide is written for that reality. Every recipe
assumes a developer laptop with Claude Code, an API key or provider credentials
someone else issued, a GitHub org with Actions, a Confluence space, and a chat
channel — and names, every time, the ask you have to make when a step needs
more than that.

It is also written with the sister site's conviction: a technique you haven't
bounded is a demo, not a system. Every unattended job here has a budget, a turn
cap, a permission mode, and a kill switch before it has a prompt.
